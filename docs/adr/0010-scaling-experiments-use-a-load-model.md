# 容量實驗跑在 Load Model 上，不跑真實轉錄

當受測的性質是系統的容量行為時，真實轉錄是個糟糕的量測工具：它的 Execution Time
隨著挑到哪些影片而變動，而且一次數百份 Job 的 burst 裡，每一份都會向下游 API 計費。
因此容量實驗跑在 Load Model 上，其 Execution Time 由設定指定為量測得到的平均值。
把實驗並不研究的元件替換掉，正是讓結果可歸因的前提；這項替換會被明確陳述，而不是
藏起來。

## Consequences

真實轉錄的正確性另外以少量真實 Job 單獨驗證，絕不以容量實驗為依據來宣稱。兩個實驗
證明不同的事，也就當作兩件事來報告。

基礎設施為了一次實驗而建立、事後銷毀，因此這個專案提供的證據是一次可重現的執行與它
擷取下來的 dashboard，而不是一個長存的環境。這個約束有一個值得說出來的設計後果：
一切都必須能從基礎設施程式碼重現，不能有手動步驟，也不能有只存在於運行中系統裡的
狀態。
